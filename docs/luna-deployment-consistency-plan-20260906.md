更正进程认知：看门狗是API的上级管理进程；Windows虚拟环境python启动器与实际python服务的父子关系本身不是异常，也不能作为启用了reload的证据。

已存在 scripts/deploy_research_backend.ps1，包含管理员/时间窗口/任务检查、停止任务、释放端口、采用契约、新PID及财报资金流接口检查。应增量增强它，不另造一套平行部署系统。

先检查计划任务实际动作、任务身份、SYSTEM与交互会话的权限差异。旧启动脚本遇到存活实例应明确返回“already_running，未部署新版本”。不得把Start-ScheduledTask返回成功或端口打开当作部署成功。

部署与看门狗分别使用跨会话单实例锁；维护标记是部署状态，不用它代替互斥锁。锁与状态文件位置固定、权限受控；崩溃后可恢复，不能仅靠存在文件永久阻塞，也不能仅靠时间到期自动恢复交易。

## 4. 批次B：固定版本与路径（P0，依赖A）

- [ ] scripts/及deploy/内必要小模块 | 制作不可变发布目录及manifest，保存当前和上一成功版本指针 | P0
- [ ] scripts/run_api.py、config/settings.py及实际路径解析模块 | 分离代码根、固定工作区配置根和可写数据根，按证据最小修改 | P0
- [ ] src/ai_os/strategy_version.py及运行身份模块 | 复用现有算法/schema契约，新增部署身份，避免混用不同摘要口径 | P0

发布目录采用显式文件清单，包含src、必要配置代码、providers/模板/提示和shared/python依赖等实际运行资产。不得仅git archive HEAD遗漏用户未提交修改；从当前工作树准备，清点未跟踪但必需的源码。排除.env、凭据、数据库、日志、缓存、.venv、历史报告和旧pyc。

准备过程核验复制前后文件集合和内容摘要；有并发修改则终止本次准备并报告。生成manifest后运行针对该目录的验收，封存成功版本；运行中禁止在发布目录编辑代码。后续工作区修改属于下一版本。

生产继续使用当前项目已核验的.venv解释器，源码从发布目录加载。记录解释器、依赖锁摘要及必要实际依赖版本；若依赖发生变化，必须提供兼容性/恢复证据，不能承诺仅回退源码即可恢复。

必须审计__file__相对路径、当前工作目录、shared配置加载和所有数据库单例：主market_data.db、其他SQLite、Tushare预算库、缓存、checkpoint、日志、知识及提示资产。可写数据固定在原有明确绝对路径，不能落到版本目录或误建空库。记录脱敏数据库身份和schema；同一数据身份不等于内容永远不变。

发布manifest至少含release_id、构建时间、文件集合/摘要算法版本、artifact_hash、算法版本、schema期望、依赖身份。运行接口返回启动时冻结的release_id、artifact_hash、PID、进程启动时间、boot_id、代码目录、解释器、数据身份、契约校验和部署就绪状态。

建议扩展现有system路由提供GET /api/v1/system/runtime。启动先验证manifest，再导入应用，并确认关键模块__file__位于预期发布根；防止sys.path从工作树混入模块。通过封存目录和来源核验保证身份可信，不能声称文件hash本身证明了所有Python模块已加载。

接口不得每次重新计算磁盘hash作为“当前运行版本”。如检测到运行目录被改，返回独立disk_drift标记、使部署就绪失败并告警，不热重载。接口遵循现有认证/绑定范围，敏感路径和配置仅返回必要脱敏身份。

## 5. 批次C：可恢复部署事务（P0，依赖B）

- [ ] scripts/deploy_research_backend.ps1及辅助模块 | 持久化部署阶段、所有者、预期版本、上一版本及失败恢复结果 | P0
- [ ] ../scripts/start_adaptive_learning_backend.ps1 | 识别维护阶段，仅启动已提交版本，阻止旧看门狗抢先启动 | P0
- [ ] src/api/app.py及现有任务入口 | 接入部署维护门禁，覆盖启动恢复、定时、手动触发和后台补采 | P0

严格顺序：

1. 取得部署锁；校验管理员权限、绝对路径、计划任务身份、版本准备/隔离结果和非交易窗口；保留现有更保守时间限制。
2. 写维护状态并阻止新任务入场，等待现有工作结束，使用有界预算。先检查running_tasks再停机存在竞态，必须验证门禁真正生效；无法排空则部署退出并恢复原状态。
3. 停止本服务管理任务/已确认看门狗，按PID、创建时间、命令、路径、祖先关系验证实际服务身份后停止。优先正常退出，超时升级停止只针对已核验进程；PID复用或陌生监听者直接失败。
4. 确认端口释放、旧服务和相关在途worker结束，才切换。不能用SessionId=0、进程名或历史日志PID单独决定终止目标。
5. 保存旧版本指针、运行契约及必要SQLite一致性备份；从新发布目录验证/采用既有契约。禁止由工作区脚本替新发布版本计算契约。
6. 启动新版本，保持业务任务暂停但允许就绪验收。启动恢复、定时补跑、通知、学习及交易不能在验收前执行。
7. 对照manifest、启动身份、真实监听PID/创建时间、模块来源、数据身份/schema和接口行为；全部成功后原子提交当前版本指针，解除维护、恢复唯一看门狗与调度。
8. 保存独立部署报告。只在该事务全部成功时返回exit 0；失败返回非零，即便已成功回退。

部署每阶段均有期限，状态写入采用原子替换。进程中断后下一次执行读取持久阶段并核验真实状态，不能盲目删除维护标记或直接启动最新目录。稳定启动控制器和看门狗自身升级要有明确交接，旧看门狗仍在内存时不能假定它已理解新标记。

首次迁移必须先捕获旧实例实际来源。若只知道磁盘现状、无法重建旧进程启动时版本，明确rollback_unavailable；不得把20:22磁盘代码当成18:55进程快照。先完成隔离验证并建立可启动的基线版本，再计划生产切换。

失败恢复：新实例停止、端口释放、恢复兼容的上一版本和相应运行契约，复验身份及就绪后才恢复原调度状态。恢复失败保持维护并报告准确恢复命令。通常只回退源码/指针/兼容契约；不得自动以旧DB覆盖期间新增业务数据。schema或依赖不兼容时停止自动回退，保留现场。本专项原则上不引入业务schema迁移。

## 6. 批次D：行为验收与测试（P0，依赖A—C）

- [ ] tests/unit/scripts/、tests/unit/api/、tests/unit/infrastructure/ | 版本身份、事务阶段、门禁及错误语义测试 | P0
- [ ] tests/integration/ | 真实隔离子进程、占用端口、看门狗、恢复和持久化验证 | P0

隔离必须显式指定临时数据库、预算库、缓存、输出及独立空闲端口；禁用生产调度/交易/通知/学习写入。测试前核验所有单例实际目标；不得在8888或生产库制造故障。

必验矩阵：

| 场景 | 必须得到的结果 |
|---|---|
| 服务仍存活、重新运行普通启动命令 | already_running且明确未部署；无第二服务 |
| 两次并发部署、两个看门狗、SYSTEM与交互会话 | 同一目标最多一个部署事务及一个管理实例 |
| 修改工作区或准备期间修改文件 | 已发布版本保持不变；准备中变化导致失败 |
| 运行目录被改、混入工作区模块、错manifest | 拒绝就绪，不能报告新版本通过 |
| 旧看门狗在释放端口时抢先拉起 | 门禁阻止竞争；陌生/错误实例不被当作成功 |
| PID复用、端口被其他应用占用、权限不足 | 不停止无关进程；失败阶段和退出码准确 |
| 维护前后同时触发任务 | 排空后无新任务进入；验收前不触发补跑或交易 |
| 启动失败、健康200但hash错误、行为缺字段 | 部署失败并实际验证恢复结果 |
| 部署进程在各关键阶段终止再启动 | 从磁盘状态和真实进程恢复，无双实例、无假成功 |
| 新版本目录启动 | 使用原有明确数据身份，无空库和错误相对路径 |
| 旧版本/契约/依赖不兼容 | 明确无法自动恢复，维护状态与现场可追踪 |
| 恢复成功 | 新版本部署仍标失败，单列rollback_verified |

生产接口行为验收与数据内容验收分开：

- score_display：用具有决策的隔离库验证scanner/decision等相关真实路由返回正确结构和数值。生产若无样本则标not_applicable并引用隔离行为证据，不能注入假生产记录。
- quote_enrichment_status：旧记录允许null；新候选通过真实get_stock_evidence → candidate_evidence_enricher →持久化→API读取路径验证available/failed/not_scheduled，关闭重开临时库后不丢失。成功保留真实来源/日期；失败和未调度原因不能混写。不能要求旧记录凭空出现新字段值。
- 不能以某一股票的外部财报/资金流当天成功作为代码部署身份的必要条件；外部数据不足单列，不能掩盖hash或接口错误。
- 保留现有评分/规则回归。完整AI研究未跑时ai_run_verified=false；本次只读接口验收不能标为生产完整AI跑通。
- 不使用仅mock立即异常替代真实超时/进程恢复；计时留合理容差，所有等待有上限。
