- HTTP 200，**688 秒**，无错误
- **5 只候选深度分析 5/5 成功**（上个会话是 0/5，因额度耗尽）
- **全部给出 `Underweight`**，`deep_score` 38/100

**这不是故障，是模型的判断**，且论证具体到证据层：

> 技术面：09-18 涨停、量比 1.72x，但**仍低于 137.37 高点，属回撤反弹未确认突破**

最后一句值得注意：模型**主动拒绝**从那个（已被评估证明统计上不成立的）历史准确率外推。

**不要**把「仍然不给 Buy」当成待修的 bug。它是模型的结论。若要改变它，只能改证据供给
或提示词，并且必须先有办法证明改得更好 —— 而那需要第三节的数据。

## 六、本会话修的两个真实 bug（细节）

### ① 跨进程写入与运行（`c4c299d`）

- `save_decisions_batch` 原是 `SELECT` 再 `INSERT/UPDATE` 的 check-then-act。唯一约束落地后
  并发会**整个批次回滚**。改为单条 `ON CONFLICT DO UPDATE RETURNING id`。
  **验证**：两个真实进程抢同一只票，5/5 轮都成功且拿到同一 id，最终 1 行。
- 新增**数据库租约**（非锁文件 —— 锁文件崩溃后残留会永久阻塞，租约过期自愈）。
  **验证**：两进程 barrier 后抢锁，5/5 轮恰好一个胜出。释放校验所有权。

### ② 深度结果被午盘扫描抹掉（`3883018`）

journal 去重后每天只剩一行，`save_strategy_decision` 用 `INSERT OR REPLACE` 覆盖它，
而 `get_cached_deep_analyses` **读的就是这张表** —— 于是「午盘跳过深度分析」会抹掉
当天真实评级，进而清空缓存（`deep_rating` 是买入闸门的输入）。

修法：**没有产出模型结果的扫描，不覆盖已存储的模型结果**（upsert 上一个 WHERE）。
代价：这些行的 `strategy_decision` 保留早盘的技术分；**决策路径不读它**，只有展示与
评估组装件读，而 `decision_journal` 每次都更新。

**顺带发现 `strategy_decision` 有两条独立写入路径**（`_insert_strategy_decision` 与
`save_strategy_decision` 各写一遍 `INSERT OR REPLACE`），已合并。

### ③ 市值字段互换（`b5517f9`，**未部署**）

腾讯 `qt.gtimg.cn` 的波浪号报文是 **44=流通市值、45=总市值**，两处解析器都写反了。

**证明**：腾讯源 66,006 行里 `值[44] > 值[45]` **出现 0 次**，相等 37.2%（全流通股）；
tushare 源呈镜像。实盘报文：中芯国际 `[44]=2440.72`、`[45]=10445.96`，修正后流通占比
23.4%，与其科创板股本结构吻合。

**影响**：41.38% 的股票存着「总市值 < 流通市值」；扫描器 `SCANNER_MIN_MARKET_CAP=20亿`
**错误排除 279 只**；等权基准的可投资域用同一字段过滤。

**那个测试本来抓不到它** —— 夹具写的是 `values[44]=1500 / values[45]=1000`（即 44 > 45），
**这种排序在真实报文里从未出现**。它是照着解析器写的，不是照着数据源写的。已改为
真实排序并加不变量断言 `market_cap_yi >= float_mcap_yi`。

## 八、操作经验（血泪，能省很多时间）

### 换行符：`git diff` 会骗你

`core.autocrlf=true`，所以：
- **git blob 恒为 LF** —— 拿它与工作区比对**判断不出**换行符是否正确
- **`git diff --stat` 会把整个文件的 CRLF→LF 转换显示成「几十行改动」**

**正确参照是 `runtime/releases/<最新>/...` 下的部署副本。** 本会话用 Python 替换文本时
两次把 CRLF 文件转成了 LF（`read_text()` 的通用换行吃掉了 CR），都是靠比对部署副本才发现。

**做任何 Python 文本替换后，必须对照部署副本核对换行符。**

### `git stash pop` 也会转换换行符

它做一次 checkout，同样受 autocrlf 影响。**用它验证「测试在无修复时会失败」之后，
必须重新核对换行符。**

### 不要把 `timeout N pytest ... | tail` 的 `$?` 当 pytest 退出码

它取的是 `tail` 的。本会话因此把一次**被超时杀掉、根本没跑完**的运行误读成成功。
要拿真实退出码就别接管道，或写 `PYTEST_EXIT=$?` 到文件。

### 测试可能在生产不具备的 schema 上跑绿

`decision_journal` 的唯一索引原本只由**迁移脚本**加到生产库，**不在 schema 定义里**
—— 于是全新库（含所有测试）没有约束。这类不一致是**静默**的。本会话把它写进 schema 后，
5 个测试立刻失败，因为它们依赖的正是生产不可能有的行为。
