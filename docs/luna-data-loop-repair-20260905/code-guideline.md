# 实施规范

- 先记录 git status，保留已有修改；不覆盖根目录既有规划文件，不做无关重构。
- 使用 apply_patch 修改文件，沿用项目命名与类型约定；大文件局部修改，不整文件重写。
- 复用现有资金流判定函数，单一语义来源；flow_state、flow_status 如继续并存，必须明确映射及所有写入者。来源数组只含真实来源。
- 零值和缺失分开；NaN、无穷值、脏字符串不可悄悄转换为有效零。净额、大单净额、主动买卖量分别标注口径和单位。
- 日期至少区分交易日、报告期、公告可知时间、抓取时间；API 请求成功不保证数据日期合格。
- 异常区分权限、限流、网络超时、解析失败、有效空结果、陈旧和覆盖不足。禁止 except 后默认写 positive 或完整状态。
- 请求预算包含重试及多个进程；缓存不能把同源记成多个独立来源，也不能将 EOD 作为实时成交价。
- 诊断缺字段前，检查保存白名单、嵌套 JSON、API 合并逻辑和真实消费者；不可仅因顶层缺字段就断言整个系统没有数据。
- 回归覆盖同证据在内存→落库→重读→门禁的等价性；补齐不能自动通过其他风险门禁。
- 对冻结同一输入比较修复前后，评分公式和权重应一致；因修复陈旧字段而改变的方向/阻断原因必须单列解释。
- 实跑必须使用明确隔离的数据库副本与输出目录；save_to_journal=False 或 execute_paper_trades=False 单个开关不能作为全部副作用隔离证据。
- 不将当前交易日缺口、未入选补齐、未到期学习标签混为故障；成功率给出正确分母和样本范围。
- 记录确切测试命令、退出码和失败项。现有 708 项通过只是旧基线，不证明新增发现已修复；新增回归通过后再执行适当全量测试。
- 验收中不输出 token、认证文件内容或带密钥的 URL；报告引用端点名、日期、统计与脱敏错误即可。
- 不新增会员、定时任务或扩大交易范围；复用已有调度。部署保持 --reload 关闭，运行契约不匹配须定位原因。
