# 全项目精简优化需求

## 目标

降低 Adaptive Investment Intelligence 项目的重复功能、重复入口、重复查询和重复运行职责，让每项能力只有一个明确的主实现和一个稳定的展示入口。

## 不可变边界

- 不改变选股公式、候选池、评分、排序、阈值、Top N、买卖方向或学习规则。
- 不改变现有交易安全门、数据来源优先级和运行端口配置。
- 不删除仍被 Replay、Decision、兼容 API 或后台任务使用的通用对比、审计和回放能力。
- 删除或合并前必须保留兼容别名、迁移说明或可验证的 404/保留行为。

## 优化范围

- 后端：路由重复、兼容入口、重复数据库查询、重复缓存、调度与服务生命周期职责。
- 前端：命令、导航、页面和请求分支的重复入口；只保留与后端主能力对应的页面。
- 工程：生成产物、临时文件、配置入口、文档计划和运行时发布边界。
- 验证：每批改动都需要证明系统健康、数据库路径/端口不变、核心决策输出口径不变。

## 交付方式

先盘点并建立能力清单，再按 P0/P1/P2 分批实施。每批只改一个职责边界，保留现有未提交用户改动，不做大范围格式化或无关重构。
