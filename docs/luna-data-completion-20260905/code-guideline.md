# Luna实施规范

- 先读取项目规则和本组三份文档。保留当前脏工作区，使用apply_patch作局部修改，不重置仓库、不覆盖原规划、不顺手重构。
- 命名沿用现有ts_code、trade_date、end_date等字段；新增字段附口径说明，保持旧API兼容。大文件只局部编辑；新模块按职责拆分，避免超长单文件。
- 不改选股评分、阈值、排序公式、候选数量策略、买卖风控和学习权重。最新数据可改变结果，但不能以补数据为由更改规则。
- SQL参数化，迁移可重复执行；唯一键应包含必要代码、端点、报告期和版本维度；逐批事务，检查点只在数据成功提交后推进。不得以关闭唯一约束处理重复数据。
- 生产与隔离DB显式注入，SQLite backup创建一致副本；检查模块级DB引用及其他持久化出口，不能仅靠execute_paper_trades=False宣称隔离。
- token不进入日志、缓存键、URL或报告。预算持久化只存不含凭据的账户标识；跨进程限速需原子操作，重试计入预算，网络调用期间不持有SQLite长事务。
- 状态至少区分not_attempted、available、empty、stale、permission_denied、rate_limited、timeout、parse_error；数据原因和业务方向分开。不能把empty直接判定为停牌。
- 保留真实零值；避免使用a or b选择数值而覆盖0；NaN/无穷和脏字符串明确无效。金额/股数/手数换算一次并标单位。
- 原始OHLC与复权因子分开保存；日期、锚点和复权口径明确，最新因子不可泄漏进历史回放。修改指标输入口径不在授权范围内。
- 报告期不等于公告时间；修订版本不可用今日信息覆盖历史可知证据。三表不同报告期不得拼成完整同一期；缺公告时间显式标记历史不可用。
- 单季利润/现金流仅在可比累计报表齐全时差分；一季度直接使用该期值，跨年度不相减；资产负债指标不做累计差分。
- 财务和资金流证据分别保留；任何单接口失败不得删除已成功部分。标准执行资金流仍复用现有四态判定，主动成交量代理不等同真实净流入。
- 多期数据的AI输入须记录实际期数/日期/来源；控制提示长度时用结构化摘要并保留原始证据引用，不能静默退回最新一条。验收必须避免复用旧深度缓存掩盖新数据路径。
- 测试验证消费者行为、并发配额、失败恢复、分页截断、幂等、点时可知性及隔离副作用；不通过修改旧断言来掩盖回归。先针对测试，再全量；记录命令、退出码和实际输出。
- 冻结输入的确定性评分应相同；新证据改变方向/阻断需解释，不把LLM随机性当作确定性公式回归。无成交不是验收失败指标。
- 保留补采前数据备份与本轮批次记录，回滚代码只撤回本轮差异；不整库覆盖回滚新成交或后续数据。部署流程使用现有脚本，生产不开reload；管理员权限不足明确报告。
- 完成报告逐项对应开发计划，未做历史覆盖审计、跨进程预算或真实消费验收的条目保持未完成，不把环境/数据边界掩盖为全部通过。
